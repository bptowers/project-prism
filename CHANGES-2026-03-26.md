### 3. Fixed Gemini JSON parse errors
**File:** `functions/src/llm/gemini.ts`
**Root cause:** With 2000 records the pipeline began hitting deals whose notes contained curly brace characters `{}`. Gemini would return valid JSON followed by trailing commentary also containing `{}`. The original regex `/\{[\s\S]*\}/` was greedy — it matched from the first `{` to the last `}` in the entire response, capturing the trailing text and producing invalid JSON.
**Fix (two-part):**
1. Added `responseMimeType: "application/json"` to the Gemini `generationConfig` — instructs the API to return pure JSON only, eliminating the root cause
2. Added a hardened `extractFirstJsonObject()` fallback parser using balanced-bracket counting, so even if Gemini returns non-pure JSON the parser correctly identifies the first complete JSON object

### 4. Fixed pipeline funnel stage inconsistency across regions
**Files:** `functions/src/pipeline/csvParser.ts`, `hosting/src/components/dashboard/PipelineFunnel.tsx`
**Root cause:** `calculateFunnel()` only included stages that had deals in that region. Switching regions changed the stage labels, not just the counts.
**Fix:**
- Defined `CANONICAL_STAGES` — the 6 Simpro stages always shown in order: Discovery → Validation → Solution Review & Quote → Commitment → Closed Won → Closed Lost
- All stages are seeded at count 0 before accumulating data, so every region always shows the same labels
- Added `STAGE_ALIASES` to normalise legacy Salesforce stage names (e.g. "Contract Review" → "Commitment")
- Fixed division-by-zero in the conversion rate display (`Infinity%` → `—` when a stage has zero deals)

## Key Technical Notes

**Why BQ_LIMIT is not just a number change:**
The pipeline runs LLM analysis on every record (Phase 1). At 500 records ≈ 8 min; at 2000 records ≈ 15–20 min. The `runWeeklyAnalysis` function has a 540s (9 min) timeout — the 2000-record run is close to that limit. If runs start timing out, either reduce the limit slightly or break into batches.

**The 500 HTTP error on the 11:06 run:**
This was a deployment collision — a run started just before our `firebase deploy`, which restarted the Cloud Run instance mid-execution and terminated it with a 500. Not a code error.

**Funnel labels on existing reports:**
The stage consistency fix applies to future pipeline runs only. Reports already stored in Firestore were generated with the old logic and will still show inconsistent labels until the next run overwrites them.
