CLOUD FUNCTIONS DETAILS:
================================================================================

Function 1: onCSVUpload
  Trigger: Cloud Storage (gs://project-prism-uploads/uploads/*.csv)
  Flow: CSV → Parse → Validate → Analyze → Aggregate → Store
  Typical Duration: 30-60 min for 1000 records
  Output: Stored in /reports/{date} and /analyses/{executionId}

Function 2: runWeeklyAnalysis
  Trigger: Cloud Scheduler (Monday 6:00 AM UTC)
  Flow: Get latest CSV → Process through pipeline
  Typical Duration: Same as onCSVUpload
  Output: Weekly aggregated report

Function 3: getReport
  Type: HTTP GET endpoint
  Response: Latest AggregatedReport JSON
  Auth: Optional (Firebase Auth if configured)
  Example: GET /getReport

Function 4: getReportHistory
  Type: HTTP GET endpoint
  Response: Array of last 10 reports
  Auth: Optional (Firebase Auth if configured)
  Example: GET /getReportHistory

Function 5: uploadCSV
  Type: HTTP POST endpoint
  Input: CSV content + filename
  Auth: Optional (Firebase Auth if configured)
  Example: POST /uploadCSV with CSV data

================================================================================
NOTABLE DESIGN DECISIONS:
================================================================================

1. Provider Pattern for LLM Selection
   Rationale: Allows switching LLM providers without changing core logic
   Benefit: Can compare costs and quality of different providers
   Implementation: ILLMProvider interface + LLMProviderFactory

2. Batch Processing for Efficiency
   Rationale: Groups records to reduce API overhead
   Benefit: Better rate limit handling, reduced latency
   Default: 25 records per batch (configurable)

3. Execution Context Tracking
   Rationale: Complete audit trail of each pipeline run
   Benefit: Debugging, monitoring, compliance
   Storage: Firestore /executions/{executionId}

4. PII Detection & Scrubbing
   Rationale: GDPR/privacy compliance, data security
   Benefit: Automatic protection of sensitive data
   Configurable: Can be disabled if needed

5. Comprehensive Error Handling
   Rationale: Production reliability
   Benefit: Partial failures don't block entire pipeline
   Strategy: Continue with valid records, log errors
