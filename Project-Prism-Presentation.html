Design Principle

Provider-Agnostic by Design

The LLM layer is modular and composable. Swap providers via configuration — no code changes required.

Phase 1 Default
Claude

Opus 4 · Best-in-class reasoning for nuanced sales context

GPT

OpenAI · Alternative provider, config-swappable

Gemini

Google · Alternative provider, config-swappable

How it works: A common LLMProvider interface abstracts all API calls. Provider selection, model version, and API credentials are config-driven. Swap Claude for GPT or Gemini by changing a single environment variable — zero code changes.

Security & Compliance

Data Privacy Considerations

Action Required

Review whether sending SFDC opportunity data to external LLM APIs requires additional security clearance or legal review. Flag with Steve's team in Week 1.

Built-in Safeguards

  • ✓PII detection and scrubbing before LLM processing
  • ✓No customer-identifiable data in prompts (deal IDs only)
  • ✓API keys stored in secure environment variables
  • ✓No data retention — process and discard

Architecture Mitigations

  • ◆Provider-agnostic design allows switching to an on-prem or private-cloud LLM if required
  • ◆Data minimization — only send note text, stage, and region; strip all unnecessary fields
  • ◆Audit logging of all LLM API calls for compliance trail
  • ◆Hosting decision (Vercel, internal VM, or cloud) determines data residency
